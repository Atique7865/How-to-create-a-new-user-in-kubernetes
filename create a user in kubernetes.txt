To create a Kubernetes user named **hasan** using **certificate-based authentication**, follow these steps:

---

## **Step 1: Generate a Private Key and CSR for Hasan**
First, create a private key for the user:

```bash
openssl genpkey -algorithm RSA -out hasan-key.pem
```

Then, generate a **certificate signing request (CSR)** with the username **hasan** and an optional group (e.g., `developers`):

```bash
openssl req -new -key hasan-key.pem -out hasan.csr -subj "/CN=hasan/O=developers"
```

- `CN=hasan` → The username in Kubernetes.
- `O=developers` → The group name (optional but useful for RBAC).

---

## **Step 2: Sign the CSR with Kubernetes CA**
To authenticate users, Kubernetes requires a certificate signed by the **Kubernetes CA**. Use the CA certificate and key from your cluster (usually located at `/etc/kubernetes/pki/ca.crt` and `/etc/kubernetes/pki/ca.key`).

```bash
openssl x509 -req -in hasan.csr -CA /etc/kubernetes/pki/ca.crt -CAkey /etc/kubernetes/pki/ca.key -CAcreateserial -out hasan.crt -days 365
```

Now, `hasan.crt` is a signed certificate that Kubernetes will recognize.

---

## **Step 3: Configure Kubernetes to Use the New User**
Add Hasan to the **kubeconfig file**:

```bash
kubectl config set-credentials hasan --client-certificate=hasan.crt --client-key=hasan-key.pem
```

Create a **new context** for Hasan:

```bash
kubectl config set-context hasan-context --cluster=kubernetes --user=hasan
```

Switch to the new context:

```bash
kubectl config use-context hasan-context
```

---

## **Step 4: Assign RBAC Permissions to Hasan**
By default, Hasan has **no permissions** in the cluster. To grant access:

### **Option 1: Assign Direct Permissions to Hasan**
If you want **Hasan** to access pods:

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: hasan-rolebinding
  namespace: default  # Change if needed
subjects:
  - kind: User
    name: hasan  # Must match CN=hasan in the certificate
    apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: developer-role
  apiGroup: rbac.authorization.k8s.io
```

Apply it:

```bash
kubectl apply -f hasan-rolebinding.yaml
```

### **Option 2: Assign Hasan to a Group (Recommended)**
If you used `O=developers`, you can create a **ClusterRoleBinding** instead:

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: developers-binding
subjects:
  - kind: Group
    name: developers  # Must match O=developers in the certificate
    apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: ClusterRole
  name: developer-role
  apiGroup: rbac.authorization.k8s.io
```

Apply it:

```bash
kubectl apply -f developers-binding.yaml
```

---

## **Step 5: Verify Hasan’s Access**
To check if Hasan has access:

```bash
kubectl auth can-i list pods --as=hasan
```

Or if Hasan is in the **developers** group:

```bash
kubectl auth can-i list pods --as-group=developers
```

---

## **Step 6: Use Hasan’s Credentials**
If Hasan needs to access the cluster, share the following files with him:
- `hasan.crt` (user certificate)
- `hasan-key.pem` (private key)
- The cluster CA certificate (`ca.crt`)

He can then configure his **own kubeconfig file** to use these credentials.

---

### **How to Remove Hasan?**
To remove the user:

```bash
kubectl config delete-context hasan-context
kubectl config unset users.hasan
```

To remove the RBAC permissions:

```bash
kubectl delete rolebinding hasan-rolebinding
kubectl delete clusterrolebinding developers-binding
```
